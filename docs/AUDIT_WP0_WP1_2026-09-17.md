## findings

### Positive findings (verified, not merely asserted)

- **Freeze discipline holds.** `freeze.json` (23:53:00Z) was committed in `25638ae` before the first invocation (23:54:47Z). None of the five frozen files changed afterward. Every run's manifest embeds the identical freeze.
- **Freeze-before-observation is corroborated for HHEM.** The HHEM remote-code module cache (`.models/.hf_modules/…/hhem_hyphen_2_dot_1`) was *created* at 19:54:59 EDT (23:54:59Z). That falls inside the first `hhem-1` run's 12.7 s load window and after the freeze commit, so this code path had not loaded HHEM before the freeze. No equivalent trace exists for the NLI model (N4).
- **Source identity holds.** Each run records its commit, a clean `status_porcelain` (only the evidence directory untracked) and source hashes equal to the git blobs at `5888d2c` and `7adfeb9`.
- **The accounting repair is truthfully characterized.** The `5888d2c..7adfeb9` diff to `probe.py` touches only `model_calls` bookkeeping in exception paths. `normalize()`, the threshold, the adapters, the fixtures and the protocol are unchanged.
- **Raw and normalized evidence are genuinely separate.** Normalized rows carry no `native_output`, and raw rows carry no `verdict`. Every row links by `raw_record_sha256` (canonical JSON) and `input_sha256`, and both verifiers recompute these.
- **Labels are isolated.** `adapter.infer(premise, claim)` receives exactly two strings. Fixture `id`, `category` and `expected` never cross the boundary. This is covered by a test that asserts call arguments, and it matters because fixture IDs such as `negation` would leak labels.
- **Failure accounting is designed well.** Load, inference, normalization, non-finite and invalid-resource failures produce complete error rows, a non-zero exit and `completed_with_errors`. Abstention and error remain distinct, and overwrite is refused. All of this is exercised with fakes. No real failure occurred, and the builder does not claim one.
- **The HHEM adapter is semantically faithful.** Direct forward plus softmax[1] equals upstream `predict()` exactly on all 12 fixtures.
- **Repeatability holds on this host.** Both builder pairs and the independent auditor rerun are bit-identical across 18 runs.
- **Scope restraint is good.** There is no runtime, router, server or Bus fork. The Reality Audit minimum is documentation only. Negative and limiting language appears throughout RESULTS and the handoff.

### Defects and observations

Items marked **D** are blocking, meaning they must be addressed before acceptance. Items marked **N** are non-blocking.

- **D1 — Architectural status is not recorded.** Governing Sprint 001 on `main` requires, for WP0, "implementation-class metadata for experimental candidates", and for WP1, to "classify it as `CONTROL_A`, `CONTROL_B`, `MASI_TARGET`, or `INFRASTRUCTURE`", with the exit condition "their architectural status is explicit". These requirements were on `main` from `2f2a10e` (15:58 EDT), before the freeze. The `CANDIDATES` table, run manifests and `RESULTS.md:16` ("Class / parameters" meaning model class) carry no implementation class. The builder's own base (`c918252`) did not yet require it, which explains the gap without removing it.
- **D2 — Pre-doctrine specialization framing.**
  - (a) The frozen contract's thesis matrix (`WP0_WP1_CONTRACT.md:28`) defines H2 solely as adapted-versus-untuned-base, which is governing **H2A**. It omits **H2B** (purpose-built specialization), the `C_A/C_B/T` controls and falsifier 2 ("general-model adaptation explains the gains"). The builder's `RESEARCH_THESIS.md:118` crosslink calls this matrix the fix for "the minimum thesis/control distinctions". WP0's "tighten the primary thesis and falsifiers" deliverable is therefore not met under current doctrine.
  - (b) `HANDOFF:101` ("E001 split/labels/metrics/base selection"), `STATUS.md:55` ("training remains gated…") and `WP0_WP1_CONTRACT.md:117` ("E001 … training authorization") carry the old learned-specialization E001 framing. Issue #3 is now "MASI-E001 — purpose-built Empathy semantic-observation intelligence".
  - (c) The results table juxtaposes a 3/12 equality floor with 12/12 learned specimens, and no statement blocks reading that as a capability deficit that justifies neural complexity. The fixtures (negation, number swap, role reversal, subset, modal) were never tested against a *competitive* transparent system.
- **D3 — The interchangeability claim exceeds what the implementation shows.** `RESULTS.md:3` states "the frozen bounded interchangeability engineering gate passed". That holds under `protocol.json`'s failure condition ("Caller needs candidate-specific **inference** branching"), because invocation is uniform. But the contract (`WP0_WP1_CONTRACT.md:17`) says the gate fails "if the caller requires implementation-specific branches", and `probe.py:83` (normalization) and `probe.py:161` (artifact manifest) branch on `candidate_id == "exact-match-v1"`. Normalization into the common envelope therefore lives in the caller and is keyed by candidate and native schema. What is demonstrated is **selection among a closed, pre-registered set**. It is not substitution of arbitrary implementations: a purpose-built target with a different native ontology, such as three-way support/contradiction/insufficiency with evidence spans, would require editing the caller and the frozen registry. "Heterogeneous" (`WP0_WP1_CONTRACT.md:11`, `HANDOFF:26`) is true of architecture and objective only. Both learned candidates share one HF/PyTorch softmax-classifier stack and one adapter class. The builder partly disclosed this ("both are text classifiers").
